# ВОЛЧЬЯ ХВАТКА — ТЗ И СТАРТОВЫЙ ПРОМПТ ДЛЯ CODEX

## 1. ЗАДАЧА

Создать с нуля современный, быстрый и адаптивный продающий сайт российского бренда «Волчья Хватка» с собственным кодом, собственным хостингом и простой административной панелью для редактирования контента.

Сайт не должен быть конструктором. Нужен самостоятельный проект, который можно развернуть на VPS или Node.js-хостинге.

Главная цель первой версии — быстро запустить продажи двух основных комплектов:

1. Две тренировочные шашки + базовый видеокурс.
2. Две тренировочные шашки + курс «Мастер».

Дополнительные товары показываются внизу страницы и не отвлекают от основных комплектов.

---

## 2. КОНТЕКСТ БРЕНДА

Название: «Волчья Хватка».

Бренд существует с 2015 года.

Основные подтверждения доверия:

- работа с 2015 года;
- более 25 000 продаж на маркетплейсах за последние два года;
- более 60 000 клиентов за всё время;
- более 18 600 участников сообщества ВКонтакте.

Не использовать заявления «№1», «лучшие в России» и иные неподтверждаемые превосходные формулировки.

Позиционирование:

- тренировочные шашки;
- обучение фланкировке;
- двигательная активность;
- координация;
- дисциплина;
- безопасная самостоятельная практика;
- без агрессивной и воинственной подачи.

---

## 3. ТЕХНОЛОГИЧЕСКИЙ СТЕК

Использовать:

- Next.js 15+;
- App Router;
- TypeScript strict;
- PostgreSQL;
- Prisma ORM;
- NextAuth/Auth.js или собственную защищённую сессию;
- Zod для валидации;
- React Hook Form;
- Tailwind CSS;
- ESLint;
- Prettier;
- Vitest или Jest для базовых тестов;
- Playwright для проверки ключевого пути покупки;
- Docker Compose для локального запуска PostgreSQL;
- хранение изображений локально в MVP с возможностью последующего перехода на S3-совместимое хранилище.

Не использовать тяжёлую внешнюю CMS.

Административная панель должна быть частью этого же приложения.

---

## 4. ОСНОВНЫЕ ПРИНЦИПЫ

1. Mobile first.
2. Максимально короткий путь от первого экрана до заказа.
3. На первом экране должна быть одна главная кнопка: «Выбрать комплект».
4. Не использовать классическую корзину для двух основных товаров.
5. По кнопке «Купить» открывать форму заказа с уже выбранным комплектом.
6. Все тексты, цены, изображения, отзывы, FAQ и товары должны редактироваться через административную панель.
7. Сайт должен работать даже до подключения Робокассы: в режиме тестового заказа заявка сохраняется в базе.
8. Не добавлять функции, которых нет в ТЗ.
9. Не придумывать реальные юридические реквизиты, токены, ключи и ссылки.
10. Все интеграции делать через переменные окружения.

## 8. ПРОСТАЯ АДМИН-ПАНЕЛЬ

Маршрут: `/admin`.

### 8.1. Авторизация

Первая версия:

- один или несколько администраторов;
- email + пароль;
- пароль хранится только в виде хеша;
- защищённая серверная сессия;
- ограничение попыток входа;
- выход из системы;

Создать seed-скрипт для первого администратора через переменные окружения:

- `ADMIN_EMAIL`;
- `ADMIN_PASSWORD`.

Не хранить пароль в репозитории.

## 19. ТЕСТЫ

Минимально проверить:

1. Главная страница открывается.
2. Основные товары загружаются из базы.
3. Администратор может войти.
