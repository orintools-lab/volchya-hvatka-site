# Content Model — «Волчья Хватка»

## 1. Назначение

Документ определяет, какой контент редактируется через административную панель,
из каких полей он состоит и как отображается на публичном сайте.

Главный принцип: администратор редактирует понятные сущности и поля, а не
конструирует страницу вручную.

Админка не является page builder:

- нельзя создавать произвольные секции;
- нельзя менять сетку и расположение блоков;
- нельзя вставлять JavaScript;
- нельзя задавать произвольные CSS-классы;
- нельзя редактировать HTML без серверной очистки;
- нельзя менять брендовые цвета и типографику для отдельного блока;
- нельзя нарушать обязательную коммерческую структуру страницы.

Разработчик определяет композицию, дизайн и допустимые варианты. Администратор
управляет содержанием, порядком и видимостью в установленных границах.

## 2. Типы контентных моделей

### Singleton

Одна запись на весь сайт или страницу. Например: Hero, основное видео, подвал,
контакты.

Администратор открывает одну форму и редактирует поля. Создание второй записи
невозможно.

### Collection

Упорядоченный список однотипных записей. Например: преимущества, FAQ, отзывы,
показатели доверия.

Администратор может:

- создать запись;
- изменить запись;
- скрыть или показать;
- изменить порядок;
- удалить с возможностью восстановления, если модель поддерживает soft delete.

### System collection

Коллекция с ограниченным составом или дополнительными бизнес-правилами.
Например: два основных комплекта и дополнительные товары.

Администратор редактирует содержимое, но не может нарушить системные ограничения.

### Legal singleton

Одна юридическая страница с фиксированным route. Текст редактируется, но маршрут
и назначение страницы остаются неизменными.

## 3. Общие поля

Поля ниже используются во всех применимых моделях.

| Поле | Тип | Назначение |
|---|---|---|
| `id` | системный идентификатор | Стабильный внутренний идентификатор. Не редактируется. |
| `visible` | переключатель | Показывать запись на публичном сайте. |
| `sort` | целое число | Порядок внутри коллекции. Чем меньше число, тем раньше элемент. |
| `createdAt` | дата и время | Дата создания. Только для чтения. |
| `updatedAt` | дата и время | Дата изменения. Только для чтения. |
| `deletedAt` | дата и время | Soft delete, если модель его поддерживает. Не редактируется напрямую. |

### Правила `visible`

- Скрытая запись остаётся в админке.
- Скрытая запись не попадает в публичные запросы.
- Скрытие не равно удалению.
- Родительская скрытая секция скрывает все дочерние элементы.
- Дочерний элемент сохраняет собственный `visible`.

### Правила `sort`

- Порядок применяется только внутри одной коллекции.
- Одинаковые значения разрешены только при наличии стабильного вторичного
  порядка.
- Админка показывает кнопки перемещения или drag-and-drop с клавиатурной
  альтернативой.
- Сохранение нового порядка выполняется атомарно.

### Правила текстовых полей

- Пробелы в начале и конце удаляются.
- Пустая строка сохраняется как отсутствие необязательного значения.
- Заголовки не содержат HTML.
- Основной текст поддерживает обычный текст или ограниченное форматирование.
- Произвольные script, iframe и inline styles запрещены.

### Правила ссылок

- Внутренние ссылки выбираются из известных route или якорей.
- Внешние ссылки проходят проверку URL.
- Разрешены только безопасные протоколы.
- Администратор отдельно указывает, должна ли внешняя ссылка открываться в новой
  вкладке.
- Ссылки на оплату и callback не редактируются как контент.

### Правила медиа

- Поле `image` выбирает запись из Media Library.
- Администратор видит preview, имя и alt-текст.
- Изображение нельзя удалить физически, пока оно используется.
- Важные изображения имеют обязательный alt-текст.
- Декоративное изображение явно помечается как декоративное.
- В модели хранится ссылка на Media, а не произвольный файловый путь.

## 4. Структура публичной главной страницы

Порядок основных секций фиксирован:

1. Header.
2. Hero.
3. Основные комплекты.
4. Trust Strip.
5. Основное видео.
6. Состав и преимущества.
7. Отзывы.
8. FAQ.
9. Дополнительные товары.
10. Footer.

Администратор может скрыть разрешённые секции, но не переставляет секции и не
создаёт новые типы блоков.

Header, Hero, основные комплекты и Footer считаются структурно важными.

## 5. Site Identity

**Тип:** Singleton  
**Раздел админки:** Настройки → Бренд  
**Назначение:** Общие текстовые данные бренда. Логотипы берутся из утверждённого
набора ассетов и не заменяются произвольной загрузкой без отдельного процесса
утверждения.

### Поля

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `brandName` | короткий текст | да | «Волчья Хватка». |
| `tagline` | короткий текст | да | «Фланкировка с 2015 года». |
| `foundedYear` | год | да | 2015. |
| `defaultLogoVariant` | выбор | да | Утверждённый вариант для основной шапки. |

### Ограничения

- `foundedYear` не может быть будущим годом.
- Название не должно быть пустым.
- В MVP доступен только утверждённый набор логотипов.

## 6. Header

**Тип:** Singleton  
**Раздел админки:** Контент → Шапка  
**Назначение:** Верхняя навигация публичного сайта.

### Поля

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `logoVariant` | выбор | да | Горизонтальный desktop-вариант. |
| `mobileLogoVariant` | выбор | да | Symbol only для мобильной версии. |
| `ctaText` | короткий текст | да | Текст главной кнопки. |
| `ctaLink` | внутренняя ссылка | да | Обычно якорь основных комплектов. |
| `sticky` | переключатель | да | Разрешённое фиксированное поведение. |

Навигационные пункты являются дочерней коллекцией `NavigationItem`.

### NavigationItem

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `label` | короткий текст | да | Текст ссылки. |
| `link` | внутренняя ссылка | да | Якорь или route. |
| `sort` | порядок | да | Порядок пункта. |
| `visible` | переключатель | да | Видимость. |

### Ограничения

- В Header не больше 6 видимых навигационных пунктов.
- CTA не дублируется среди пунктов меню.
- На мобильном CTA остаётся доступной.

## 7. Hero

**Тип:** Singleton  
**Раздел админки:** Контент → Первый экран  
**Назначение:** Главный оффер и основной путь к выбору комплекта.

### Поля

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `eyebrow` | короткий текст | нет | Короткая надпись над заголовком. |
| `title` | заголовок | да | Главный H1 страницы. |
| `subtitle` | короткий текст | да | Пояснение предложения. |
| `primaryButtonText` | короткий текст | да | «Выбрать комплект». |
| `primaryButtonLink` | внутренняя ссылка | да | Якорь основных комплектов. |
| `secondaryButtonText` | короткий текст | нет | «Смотреть видео». |
| `secondaryButtonLink` | внутренняя ссылка | нет | Якорь видео. |
| `image` | Media | да | Изображение двух тренировочных шашек. |
| `imageAlt` | короткий текст | да | Описание товара на изображении. |
| `background` | выбор | да | Только утверждённый вариант поверхности. |
| `visible` | переключатель | да | Видимость секции. |

### Варианты `background`

- Graphite;
- Dark Wood;
- утверждённое фоновое изображение из Media с обязательной контрастной
  проверкой.

Администратор не задаёт произвольный цвет.

### Ограничения

- `title` рекомендуется до 90 символов.
- `subtitle` рекомендуется до 180 символов.
- Primary-кнопка обязательна.
- На первом экране нет второй конкурирующей primary-кнопки.
- Hero не содержит произвольный HTML.
- Изображение не должно обрезать важные части изделий.

**Раздел админки:** Контент → Первый экран → Показатели  
**Назначение:** Подтверждённые показатели доверия.

### Поля

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `value` | короткий текст | да | Например, «25 000+». |
| `label` | короткий текст | да | Пояснение показателя. |
| `sourceNote` | внутренний текст | нет | Основание для проверки заявления. Не публикуется. |

- `sourceNote` не отображается публично.

## 9. Product

**Тип:** System collection  
**Раздел админки:** Товары  
**Назначение:** Основные комплекты и дополнительные товары.

### Поля

| Поле | Тип | Обязательное | Назначение |
|---|---|---:|---|
| `name` | короткий текст | да | Название товара. |
| `slug` | slug | да | Стабильный идентификатор. |
| `category` | выбор | да | Основной или дополнительный. |
| `subtitle` | короткий текст | нет | Короткое пояснение. |
| `description` | текст | да | Описание товара. |
| `price` | деньги | да | Текущая цена. |
| `oldPrice` | деньги | нет | Старая цена. |
| `currency` | фиксированный выбор | да | RUB в MVP. |
| `image` | Media | да | Главное изображение. |
| `imageAlt` | короткий текст | да | Alt-текст изображения. |
| `badge` | короткий текст | нет | Например, «Самый популярный». |
| `buttonText` | короткий текст | да | Текст кнопки заказа. |
| `composition` | список строк | да | Что входит в товар. |
| `benefits` | список строк | да | Преимущества. |
| `sort` | порядок | да | Порядок внутри категории. |
| `active` | переключатель | да | Можно ли выбрать для нового заказа. |
| `visible` | переключатель | да | Показывать ли публично. |

### Категории

- `MAIN` — два основных комплекта;
- `ADDITIONAL` — дополнительные товары.

### Ограничения

- Публичная главная должна иметь два активных основных комплекта.
- Цена неотрицательная.
- Старая цена отсутствует либо выше текущей.
- Активный товар обязан иметь изображение и состав.
- Скрытый товар не показывается, неактивный не доступен для нового заказа.
- Изменение товара не меняет snapshot существующих заказов.
- Удаление выполняется через soft delete.

## 29. Поведение форм админки

Каждая форма:

- показывает только поля своей модели;
- группирует связанные поля;
- объясняет ограничения;
- показывает preview медиа;
- сохраняет черновое введённое значение после ошибки;
- имеет одно основное действие «Сохранить»;
- предупреждает о несохранённых изменениях;
- показывает серверную ошибку рядом с причиной;
- фиксирует критичные изменения в AuditLog.

Для singleton форма открывается сразу. Для collection сначала показывается
список, затем форма конкретной записи.

## 30. Публикация и preview

MVP не требует сложного workflow согласования.

Используются:

- `visible` для публикации;
- `active` для операционной доступности товара или доставки;
- preview выбранного медиа внутри формы;
- безопасный предварительный просмотр секции при реализации админки.

Отдельные статусы draft, scheduled и approved не добавляются без подтверждённой
потребности.

## 31. Кэширование контента

Публичный контент группируется по тегам:

- products;
- hero;
- navigation;
- trust;
- video;
- benefits;
- reviews;
- faq;
- footer;
- legal;
- settings;
- seo.

После сохранения административная операция инвалидирует только связанные
данные. Цена при создании заказа всегда повторно получается из авторитетного
источника и не зависит от публичного кэша.

## 32. Аудит контента

Аудит обязателен для:

- изменения цены;
- изменения активности товара;
- публикации или удаления товара;
- изменения юридических текстов;
- изменения реквизитов;
- изменения ссылок;
- изменения параметров аналитики;
- удаления медиа;
- массовой смены порядка;
- восстановления soft-deleted записи.

Аудит хранит безопасные значения до и после изменения без секретов.

## 33. Критерии готовности модели

Контентная модель готова к реализации, если:

- каждое публичное значение имеет определённый источник;
- singleton нельзя случайно продублировать;
- collection имеет порядок и видимость;
- все изображения ссылаются на Media;
- ссылки валидируются;
- денежные поля проверяются сервером;
- скрытие отделено от удаления;
- системные данные не редактируются как контент;
- UI не содержит захардкоженные редактируемые тексты;
- форма админки строится из понятных полей, а не универсального JSON;
- изменение модели отражено в `DATABASE.md` и `ARCHITECTURE.md`;
- критичные изменения попадают в AuditLog.
